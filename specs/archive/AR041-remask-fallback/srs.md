# [AR041] 需求设计说明书 — 置信度触发的重掩码回退（CTR-F）

| 字段 | 内容 |
|------|------|
| AR 编号 | AR041 |
| AR 主题 | 低置信块回退到官方阈值重掩码迭代（质量修复） |
| 关联 SR | SR-041（质量鲁棒性，承接 AR040 的矩阵结论） |
| 日期 | 2026-10-25 |
| 状态 | Draft |

## 1. 背景

AR040 矩阵实测（3 prompt × 160 token）：

| cell | logp A（官方迭代） | logp D/S（整块贪心提交） |
|---|---|---|
| p1 | −1.153 | −1.312 |
| p2 | −0.848 | **−0.990** |
| p3 | −0.809 | **−1.537** |

结论：**整块贪心提交在部分 workload 上明显劣于官方阈值重掩码**。速度鲁棒（16.2×），质量不鲁棒。

## 2. 目标（冻结判定）

`FastDLLMSamplerConfig.remask_fallback`（默认关）+ `remask_fallback_threshold`（默认 0.5）：
当块级置信度 `g_min < threshold` 时，**该块回退到官方重掩码迭代**（复用仓库既有切片路径），
其余块维持投机快速路径。在同一 AR040 矩阵（3 prompts × 160 token）上：

- **H1 质量**：CTR-F 的 `logp >= logp(A) - 0.05` 的 cell 比例 ≥ 90%（即恢复基线平价）；
- **H2 速度**：`median(ms(A)/ms(R)) >= 8×`；
- **H3 账本**：`spec_remask_fallbacks > 0` 且回退块之外的行为与 D 逐位一致（`fallbacks == 0` 时与 D 逐字节一致）；
- **H4 复现**：双跑逐位一致。

任一失败 → 如实交付（不重跑凑数）。

## 3. 功能需求

### F1 回退判定与执行

**描述**：块处理开始时若 `g_min < remask_fallback_threshold`，该块不再使用整块提交，
改走官方迭代解掩（每个迭代 1 次切片前向 + 置信阈值 `threshold` 重掩码）。

**验收标准**：
- Given 低置信块，Then `spec_remask_fallbacks += 1`，该块不产生 `spec_verify_forwards`，
  且后续迭代不再重复判定（块级闩锁）；
- Given 高置信块，Then 行为与 AR039 末态一致。

### F2 与 CDF/VFG 的组合

**描述**：回退块不设 advance 交接，其提交走非融合路径（少一次融合机会），下一块正常。

**验收标准**：Given 回退后进入下一块，Then 输出正确、无异常，`degraded_calls == 0`。

### F3 账本

**描述**：`history_cache_stats` 新增 `spec_remask_fallbacks`；默认关为 0。

## 4. 非功能需求

| 类型 | 指标 | 要求 |
|------|------|------|
| 质量 | 恢复基线平价 | ≥90% cell（AR040 矩阵口径） |
| 速度 | 中位加速 | ≥8×（相对非缓存基线） |
| 兼容 | 默认关 | 与 AR039 末态逐字节一致 |
| 可靠性 | 闩锁 | 同一块不重复回退判定；回退块不破坏 KV 历史 |

## 5. 约束与假设

- 真实 checkpoint、无 mock；长几何 `stop_token_id=-1`；
- 假设 A1：低置信块正是贪心提交劣化的来源（AR040 数据支持）；
- 假设 A2：官方迭代路径在组合臂内可直接复用（`sb_available=False` 分支已存在，AR033 验证过精确性）。

## 6. 术语

| 术语 | 定义 |
|------|------|
| CTR-F | 置信度触发的重掩码回退 |
| 回退块 | `g_min < remask_fallback_threshold` 的块，走官方迭代解掩 |
| 闩锁 | 同一个块一旦回退，本轮不再重新走投机判定 |
